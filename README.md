# TokenBucket

Локальный менеджер секретов для Windows: API-токены, учётные данные, SSH-ключи.
Всё шифрование выполняется на компьютере пользователя, сеть не используется.

Автор: **Роман Бородин** <workplace-it@rambler.ru> · версия 1.0 · лицензии компонентов — `docs/licenses/`

## Возможности

- **Хранилище одного файла** (`vault.tb` в каталоге данных пользователя): проекты и группы до 8 уровней вложенности, до 10 000 записей, секрет до 1 МиБ.
- **Криптография**: XChaCha20-Poly1305 со случайным nonce на операцию; ключ данных заворачивается ключом из мастер-пароля (Argon2id, 64 МиБ, opslimit 3) или DPAPI учётной записи (Windows Hello). Параметры KDF проверяются при чтении — понижение невозможно.
- **Разблокировка**: мастер-пароль или Windows Hello; сменяемая в обе стороны; экспорт/импорт защищённого контейнера для переноса.
- **Записи**: API-токен, логин/пароль, SSH-ключ (приватный + публичный + фраза). Теги, избранное, признак «повторная проверка перед доступом», сроки действия с подсветкой истекающих/просроченных.
- **Выдача секретов**: копирование с автоочисткой буфера через 20 с (исключение из истории и облачной синхронизации), быстрая вставка по Ctrl+Alt+V с двойной проверкой получателя, выдача в переменные окружения (временно — в запущенный процесс, постоянно — в HKCU\Environment с предупреждением), сохранение SSH-ключа во временный файл с правами только владельцу.
- **Защита сеанса**: автоблокировка по таймеру (1–60 мин), блокировка при уходе из сеанса Windows и переходе в сон; единственный экземпляр через lock-файл.
- **Память**: ключи и сериализуемые секреты — в защищённых буферах libsodium (`sodium_malloc`, guard-страницы); при сохранении открытый текст не проходит через обычную кучу (собственный CBOR-писатель); аварийные дампы процесса запрещены.
- **Интерфейс**: тёмная/светлая тема, трей с состояниями и уведомлениями, сворачивание в трей, автозапуск с Windows, поиск с фильтрами и сортировкой, импорт из CSV и KeePass XML.

## Формат данных

Контейнер `TBVK` v1: заголовок (магия, версия, режим, параметры KDF, соль 16 Б) → обёрнутый XChaCha ключ данных → шифротекст CBOR. AAD покрывает весь файл от магии до конца — подмена любого байта detected до разбора. Содержимое — CBOR v3 (v2 — теги, v1 — исходная версия читаются; более новые версии отклоняются с явным сообщением). Подробности формата — в коде `src/vault/Container.cpp` и спеке `docs/superpowers/specs/2026-10-18-tokenbucket-design.md`.

## Сборка (Windows)

Инструменты: Visual Studio 2022+ (MSVC), CMake ≥ 3.30, vcpkg с манифестом `vcpkg.json` (Qt6 Widgets/Test/Concurrent, libsodium). Версии зафиксированы в `docs/build/windows-toolchain.md`.

```cmd
tools\build.cmd            # конфигурация + сборка (Release)
tools\test.cmd             # полный CTest (15 целей)
tools\package-windows.cmd  # dist\TokenBucket + zip с зависимостями
```

## Структура

```
src/
  vault/     криптография, контейнер TBVK, CBOR-писатель, атомарное хранение
  model/     дерево узлов и записи, поиск, теги, CBOR v1–v3
  app/       Application (состояния/generation/busy), IdleTimer
  platform/  Windows: DACL-файлы, Hello/DPAPI, сессия, буфер, env, быстрая вставка,
             политика дампов; Linux-ветки (отложено до отдельной задачи)
  ui/        окна, редактор, карточка, трей, тема, брендинг
  io/        импорт CSV / KeePass XML
tests/       15 целей CTest: от крипто-юнитов до e2e через реальные диалоги
docs/        спека, планы, аудит и оценка защиты, приёмка, инструментарий сборки
```

## Безопасность

Обещания и границы защиты — в спеке (§4): файл защищён от чтения без ключа и от изменения; защита от вредоносного ПО в разблокированной сессии, администратора и снимков памяти **не входит** в объём. Аудит криптографии и сводная оценка с остаточными рисками — `docs/security/`.
