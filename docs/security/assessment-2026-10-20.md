# Оценка защищённости TokenBucket — 2026-10-20

Сводная оценка по итогам целевого аудита (независимый аудитор: `audit-2026-10-20-crypto.md`; контролёр: этот документ) и внесённых исправлений. Приложение v1.0 (коммит на дату оценки).

## 1. Вердикт

Критических и важных проблем не найдено (0 Critical, 0 Important). Криптографическое ядро реализовано корректно. Уровень защиты соответствует обещаниям спецификации §4; остаточные риски ниже перечислены явно и осознанно приняты.

## 3. Исправлено по итогам аудита (коммит этой даты)

1. **TOCTOU получателя вставки**: идентичность отделена от foreground. Панель сначала возвращает исходное окно и ждёт отпускания Ctrl/Alt/Shift/Win (общий бюджет 1500 мс), затем публикует выбранное поле. После вложенных ожиданий буфера повторяет проверку записи, поколения, фокуса и модификаторов. Отмена незавершённой публикации инвалидирует её epoch; позднее продолжение не оживляет закрытую/новую операцию. Частичный SendInput освобождает только синтетические клавиши и не повторяет выдачу. Полной атомарности между последней проверкой и системной очередью ввода нет; DOM/Electron-поле без отдельного HWND также не идентифицируется.
2. **Незатёртые экспортные байты** (`MainWindow::exportVault`): копия зашифрованного контейнера в куче затирается `sodium_memzero` после записи файла и при отказе записи.
3. **Редактор без повторной проверки** (audit M-1, `MainWindow::editSelected`): записи с `reverify` теперь требуют подтверждения владельца до открытия редактора, который показывает секреты. Покрыто тестом `reverifyAskedBeforeEditorShowsSecrets` (неверный пароль → редактор не открывается; верный → открывается).

## 3a. Усиление памяти (этой же датой, отдельная волна)

1. **Защищённый CBOR-писатель** (`vault/CborWriter`, `VaultModel::toCborSecure`): раньше каждый save/create/import/switch прогонял весь открытый текст хранилища через `QCborValue::toCbor()` и промежуточные QByteArray в обычной куче. Теперь собственный энкодер пишет напрямую в `sodium_malloc`-буфер (два прохода одной логикой: подсчёт размера → запись), а `Crypto::seal`/контейнер принимают открытый текст по указателю. Побайтовая совместимость выходов с эталоном Qt фиксируется золотым тестом `secureCborGoldenByteMatch` (закодированный порядок ключей QCborMap = порядок вставки). Попутно `packPassword` больше не копирует dataKey в кучу при заворачивании (закрыт Info-2).
2. **Политика аварийных дампов** (`platform/crashpolicy_win.cpp`): с первого оператора main процесс отключает системные аварийные диалоги (`SEM_NOGPFAULTERRORBOX|SEM_FAILCRITICALERRORS`) и запрещает WER-снимки для себя (`WerSetFlags(DISABLE_SNAPSHOT_CRASH|HANG)`, динамически, отказ некритичен). Дамп — снимок всей кучи, т.е. прямой вынос секретов; теперь он не создаётся по вине самого процесса.

## 4. Остаточные риски — осознанно приняты (спека §4)

- **M-2. Постоянная env-переменная**: секрет открытым текстом в HKCU\Environment до удаления (фича по запросу владельца; диалог предупреждает, подтверждение default-No, «Стирать при выходе» доступно). Это единственный путь получить секрет без пароля вне DPAPI-границы; добровольное действие пользователя.
- **M-3. Снимок модели для отката** (`MainWindow::commitEntry`): каждая правка копирует открытый текст изменённой записи в кучу до подтверждения сохранения. Qt-контейнеры COW (копирование дёшево), затирание всех следов в RAM спекой не обещано. Рецепт на будущее: revert-лог на один элемент вместо полного снимка.
- **Чтение CBOR через QCborValue** (`VaultModel::fromCbor`): путь ЧТЕНИЯ остаётся на Qt — расшифрованный контейнер кратко существует в QByteArray, QCborValue разбирает его в обычной куче. Закрытие требует собственного декодера (непропорционально объёму выгоды на v1); до тех пор путь записи защищён, путь чтения — принятый остаточный риск.
- **Память процесса**: секреты и пароли присутствуют в памяти разблокированного приложения (Qt-строки модели, поля диалогов); защита от снимков памяти самим пользователем/админом, вредоносного ПО в сессии и администратора не входит в объём v1 (спека §4). Административно настроенный WER LocalDumps может писать дампы службой — это вне полномочий процесса (см. §3a.2).
- **Откат к старой корректной копии** неотличим от намеренного без внешнего доверенного состояния (спека §4).
- **DPAPI-граница Hello-режима**: процесс той же учётной записи потенциально может вызвать DPAPI без Hello; компромисс зафиксирован в спеке и диалоге создания.

## 5. Рекомендации (вне v1)

- revert-лог вместо полного снимка записи в `commitEntry` (уменьшает M-3);
- собственный защищённый CBOR-декодер для пути чтения (существенное изменение, отдельная задача).

## 6. Криптографический обзор аудитора (кратко)

Повторов nonce нет (24 Б CSPRNG на операцию); AAD покрывает все поля; downgrade KDF невозможен; подменённый bak приложением не принимается; результаты отменённых операций в память не применяются; сравнение ключей — `sodium_memcmp`. Полный разбор: `audit-2026-10-20-crypto.md`.
