# TokenBucket: спецификация первой версии

Статус: утверждена пользователем 2026-10-18 (включая ограничение: Ubuntu/GNOME/Wayland в первой версии — копирование и ручная вставка). Редакций после утверждения нет.

## 1. Цель и платформы

Локальное приложение для API-токенов, учётных данных и SSH-ключей, организованных по произвольным проектам и группам. Приоритеты: простота, защита сохранённых данных, быстрые действия без случайной выдачи секрета.

Пользователь выбрал Linux / Windows и Ubuntu/GNOME. Предлагаемая проверочная матрица: Windows 11 x64 и Ubuntu 24.04 LTS x64 / GNOME / Wayland. Конкретная версия Ubuntu и Wayland являются допущением этой спецификации. Другие версии и X11 не получают статус проверенных без отдельных испытаний.

Вне объёма: macOS, облачная синхронизация, интеграции с провайдерами, SSH-подключения, генерация SSH-ключей, SSH-agent, браузерное расширение. oitasc.ru и cloud.ru — примеры названий проектов.

## 2. Интерфейс и данные

C++20, Qt 6 Widgets, CMake, libsodium. Qt Core/Gui/Widgets; Qt DBus только на Linux. Конкретные версии зависимостей фиксируются в плане после проверки доступных средств сборки. Криптографические примитивы не писать самостоятельно.

Выбранный интерфейс: дерево проектов и групп слева, список записей по центру, карточка справа. Панели изменяют ширину; при недостатке места карточка открывается отдельно. Русский интерфейс, поддержка клавиатуры, подписанные доступные действия, масштабирование Windows 100–200% и GNOME 100/200%. Значение не выдаётся по одному лишь выделению строки.

Проекты и группы имеют UUID, имя и родителя; группы допускают вложенность до 8 уровней. Перенос не допускает циклов. Непустую группу/проект сначала нужно освободить от записей, затем удалить. Имена не используются как пути файлов.

Общие поля записи: UUID, проект/группа, название, заметка, URL, даты создания/изменения, избранное, признак повторной проверки. Типы:

- API-токен: секретное значение.
- Учётные данные: логин и пароль, отдельные кнопки копирования.
- SSH: исходные байты приватного ключа, необязательный публичный ключ, необязательная парольная фраза и описание. Для ключа и фразы отдельные действия выдачи.

Поиск по названиям, логинам, проектам и заметкам; не по секретам. Секреты скрыты по умолчанию. Показать — явное действие, с повторной проверкой при включённой политике, автоматическое скрытие через 15 секунд и при потере фокуса.

SSH-импорт сохраняет исходные байты, не снимает существующее шифрование ключа и не требует его парольную фразу. Поддерживаемые контейнеры первой версии: OpenSSH private key и PEM; проверка границ контейнера не означает криптографическую валидацию ключа. PPK не поддерживается. Не вычислять выдуманные отпечатки; алгоритм/отпечаток не обязательны в первой версии.

Ограничения: 10 000 записей, 1 MiB на импортируемый ключ/секрет, 64 MiB на расшифрованное содержимое, 80 MiB на входной файл. Превышение — понятная ошибка без частичного сохранения.

## 3. Шифрование и разблокировка

Содержимое, включая имена и заметки, шифруется XChaCha20-Poly1305 ключом данных 32 байта. Для каждой операции шифрования генерируется новый случайный nonce 24 байта средствами libsodium. Версионированный заголовок аутентифицируется как дополнительные данные. Простой контейнер с фиксированными размерами/длинами и зашифрованной сериализованной моделью; точная байтовая раскладка и тестовые векторы входят в план реализации.

Мастер-пароль: Argon2id v1.3, salt 16 байт, opslimit 3, memlimit 64 MiB, выход 32 байта для защиты случайного ключа данных. В первой версии принимать только эти параметры, не выполнять произвольные параметры из недоверенного файла. Пароль: минимум 12 символов, максимум 1024 байта UTF-8, без trim и нормализации, подтверждение при создании. Не хранить пароль или отдельный быстрый хеш пароля.

Windows допускает альтернативный режим Hello: ключ данных защищён DPAPI текущего пользователя, доступ в приложении предваряется проверкой Hello через interop API. Проверка Hello не является криптографической привязкой DPAPI-ключа к биометрии. Процесс той же учётной записи потенциально может обойти UI-проверку. Это различие явно показывать при настройке режима. Если Hello недоступен или отменён — доступ не выдавать.

Linux использует мастер-пароль. Windows-локальный режим не переносится прямым копированием файла: для перехода на Linux нужен защищённый экспорт. Переключение способов разблокировки требует текущей проверки, успешной записи новой оболочки ключа и только затем удаления старой. Не оставлять незаявленный запасной способ доступа.

Без пароля восстановление парольного хранилища невозможно. При утрате Windows-профиля/доступа к Hello восстановление возможно из ранее сделанного защищённого экспорта. Не вводить скрытого восстановительного ключа.

## 4. Границы защиты и память

Защищаем файл от чтения без ключа и обнаруживаем изменение шифротекста. Не обещаем защиту от вредоносного ПО в разблокированной сессии, администратора, снимков памяти или от получателя, которому пользователь передал секрет. Старую корректную копию нельзя отличить от намеренного отката без внешнего доверенного состояния.

Ключи держать в очищаемых буферах libsodium. Минимизировать копии секретов, очищать временные буферы после использования. Qt и ОС могут создавать дополнительные копии; не заявлять гарантированное удаление всех следов из RAM/swap/SSD. Не писать секреты в логи, аргументы командной строки, диагностические сообщения и crash-отчёты приложения.

Автоблокировка: 5 минут без взаимодействия с приложением, блокировка сеанса, переход в сон и ручная команда. После блокировки очистить модель, поля UI, ключи и принадлежащий приложению секрет в буфере; отменить незавершённую выдачу. Асинхронные ответы Hello не должны разблокировать уже отменённую операцию.

## 5. Сохранение и экспорт

Файл в каталоге данных текущего пользователя. На Linux каталог 0700, файлы 0600; на Windows ограниченный DACL текущего пользователя и SYSTEM. Вторая копия приложения не получает возможность параллельно изменять хранилище.

Сохранение: создать зашифрованный временный файл в том же каталоге, проверить ошибки записи/flush, заменить основной файл атомарно средствами платформы. Предыдущую успешно прочитанную версию сохранять как зашифрованную резервную копию. Не использовать fallback с прямой перезаписью основного файла. При ошибке исходный файл остаётся доступен, интерфейс не объявляет операцию сохранённой. Повреждённый основной файл не должен затереть исправную копию.

Защищённый экспорт: отдельный случайный ключ, salt и nonce, отдельный пароль, те же алгоритмы и лимиты. Экспорт не содержит DPAPI-оболочки. Импорт открывает восстановленное хранилище как новое, с новым локальным способом разблокировки; не сливает и не перезаписывает текущее молча. Проверить весь контейнер и модель до создания нового хранилища.

SSH-экспорт в файл — отдельная операция: повторная проверка при включённой политике, предупреждение о выдаче ключа за пределы хранилища, явный выбор пути. Сохранять байты без изменения. Создавать с ограниченными правами с самого начала, отказывать в небезопасном назначении или при невозможности установить права; не следовать символическим ссылкам. Перезапись только после явного подтверждения. Обычный незашифрованный экспорт всего хранилища отсутствует.

## 6. Копирование и вставка

Кнопки копирования доступны в списке и карточке с понятными подписями для клавиатуры/скринридера. Для защищённых записей каждый показ, копирование и экспорт требует новой проверки; отмена не изменяет буфер. Подтверждение привязано к записи и конкретному действию.

Обычное копирование: таймер 20 секунд. Проверять владение/идентичность своей публикации и очищать только её; чужое более новое содержимое не трогать и старый буфер автоматически не восстанавливать. При занятом буфере — ограниченная попытка и сообщение об ошибке. Аварийное завершение может оставить содержимое у ОС/менеджера; таймер не является гарантией удаления после сбоя.

Windows: исключать данные из системной истории/синхронизации предусмотренными форматами. Linux: не заполнять PRIMARY selection; сторонние менеджеры истории могут сохранять CLIPBOARD вопреки политике приложения. Не обещать универсального запрета истории.

Windows-быстрая вставка: горячая клавиша Ctrl+Alt+Space (при конфликте сообщить и предложить изменить); мини-панель поиска; фиксирование окна-получателя, показ имени процесса и заголовка, повторная проверка перед передачей Ctrl+V. Не передавать Enter. При смене окна или повышенном уровне прав отменять, оставляя доступным ручное копирование. Даже повторная проверка не даёт атомарной гарантии адресной доставки SendInput.

Ubuntu/GNOME/Wayland: первая версия гарантирует копирование и ручную вставку. Мини-панель открывается из приложения; глобальный вызов — через доступный GlobalShortcuts portal либо настроенное пользователем сочетание GNOME для команды открытия панели без секретов в аргументах. Не запрашивать RemoteDesktop-доступ лишь ради имитации Ctrl+V. Универсальную автоматическую вставку и показ чужого активного окна не включать в обещания первой версии. Это предлагаемое ограничение относительно исходного пожелания двух способов вставки требует принятия пользователем при рассмотрении спецификации.

Многострочные секреты и приватные SSH-ключи не выдавать через автоматическую вставку: только явное копирование или файл. В терминале даже вставленный перевод строки может выполнить команду.

## 7. Компоненты

- Модель: проекты, группы, записи, проверки связей и лимитов.
- Vault: криптография, контейнер, безопасная запись, импорт/экспорт; без зависимости от UI.
- Qt UI: дерево, список, карточка, диалоги и мини-панель.
- Платформенные функции: Hello/DPAPI, буфер, блокировка сеанса, горячие клавиши и вставка. Общие функции не зависят от Windows API.

Операции KDF и диска не блокируют UI. Нельзя одновременно менять хранилище и завершать устаревшую асинхронную операцию над ним. Не создавать архитектуру плагинов, сетевой сервис или базу данных без потребности.

## 8. Приёмка

1. Сборка Release и запуск на Windows 11 x64 и Ubuntu 24.04/GNOME/Wayland. Отдельно фиксировать среду и результаты; сборка Linux в WSL не заменяет испытаний GNOME.
2. Создание, изменение, перенос, удаление и поиск всех типов записей; повторное открытие сохраняет данные. Проверить Unicode и вложенные группы.
3. Криптотесты: корректное открытие, неверный пароль, изменения заголовка/шифротекста, усечение, превышение размеров, неподдерживаемые версии/параметры. Ни один отказ не выдаёт частичные данные.
4. Инъекции ошибок записи и замены: исходный файл остаётся читаем, резервная копия не теряется, интерфейс сообщает отказ.
5. Защищённый экспорт Windows → Ubuntu и Ubuntu → Windows, включая точное совпадение байтов SSH-ключа после выдачи в файл.
6. Hello: успех, отказ, отмена, отсутствие настройки, блокировка во время ожидания. Реальная успешная проверка требует устройства/учётной записи с Hello и участия владельца; заглушка её не заменяет.
7. Буфер: таймер, новое чужое содержимое, два копирования подряд, занятый буфер, блокировка приложения. На Windows отдельно проверить системную историю.
8. Вставка Windows: браузер, редактор, терминал с безопасной однострочной тестовой строкой, смена фокуса, повышенное окно, отмена. Не использовать реальные секреты.
9. Ubuntu: копирование/вставка в GNOME Terminal, браузер и редактор; блокировка сеанса и восстановление приложения; доступность выбранного способа глобального вызова.
10. Клавиатурная навигация, доступные имена и DPI. В поставке Windows — EXE с нужными библиотеками; Ubuntu — пакет .deb с зависимостями. Лицензии зависимостей приложены. Установку проверять в чистой среде.

Готовность означает прохождение матрицы с доказательствами. Непроверенная платформа или Hello отмечается как непроверенная, а не «100% готово». Подпись установщика и публикация не входят в эту спецификацию.
