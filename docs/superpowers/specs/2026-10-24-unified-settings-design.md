# Единое окно настроек TokenBucket

Дата: 2026-10-24. Основание: утверждённые вариант B и макет настроек из [общего предложения](2026-10-22-tokenbucket-improvements-proposal.md). Статус: написанная спецификация утверждена владельцем 2026-10-24; реализация этого этапа не начата.

## 1. Цель и объём

Дать владельцу одно понятное место для управления поведением программы. Сохранить действующие значения, позволить отменять неприменённые изменения и явно сообщать о неудачном сохранении. Проверки выдачи секретов остаются обязательными.

Входят пять разделов утверждённого макета: «Общие», «Безопасность», «Быстрая вставка», «Выдача секретов», «Резервные копии». Пересекающиеся F4 (восстановление существующей копии) и F5 (поведение закрытия) выполняются здесь один раз. F1–F3 — генератор, массовые действия и сохранённые представления — остаются отдельными этапами.

Сохраняются Qt Widgets, существующая тема, формат хранилища и текущая модель Windows Hello/DPAPI. Новые зависимости, синхронизация, история секретов, собственный CBOR-декодер, сертификат подписи и обход ограничений Windows сюда не входят.

База: main `2328280`. Граф Engram использован для навигации и обновлён инкрементально; выводы проверены в исходниках.

## 3. Окно и навигация

Один модальный диалог «Настройки»: слева пять разделов, справа прокручиваемая страница, снизу «Отмена» и «Сохранить». Основа — существующий [макет](../../design/2026-10-22/03-settings.png). Начальная ширина 900 логических пикселей, но не больше рабочей области минус 40; высота — по содержимому, не больше рабочей области минус 80. При ширине меньше 720 навигация заменяется верхним выпадающим списком тех же разделов; нижние кнопки не прокручиваются вместе со страницей. При первом открытии выбран раздел «Общие».

В меню «Настройки» появляется основной пункт «Настройки…» с Ctrl+,. Разрозненные пункты предпочтений заменяются этим входом. Действия смены мастер-пароля и способа разблокировки остаются отдельными операциями с текущей проверкой; из раздела безопасности доступны ссылки на них. Изменение способа разблокировки не становится обычным флажком.

Изменения элементов до нажатия «Сохранить» хранятся только в черновике. Переключение разделов не теряет черновик. Esc, крестик и «Отмена» закрывают окно без применения черновика. Тема тоже меняется после сохранения, без предварительного изменения палитры.

Повторное открытие создаёт снимок действующих настроек, а не предыдущего черновика. При блокировке диалог закрывается без сохранения. Пока модальный диалог настроек или восстановления открыт, глобальное сочетание не начинает новую выдачу; уже открытая панель отменяется до открытия настроек. Автоблокировка и блокировка сеанса продолжают работать.

## 4. Общие настройки и совместимость

Все обычные предпочтения остаются в текущем локальном QSettings `TokenBucket/TokenBucket`. Значения интерфейса хранятся стабильными кодами, а не переведёнными подписями.

| Параметр | Хранение | Разрешено | По умолчанию |
| --- | --- | --- | --- |
| Тема | существующий `theme` | system / light / dark | system |
| Автозапуск | существующее HKCU Run / TokenBucket | включён / выключен | фактическое состояние записи Windows |
| Уведомления | существующий `trayNotifications` | bool | true |
| Закрытие главного окна | новый `closeBehavior` | hide / lock-hide / exit | hide |
| Автоблокировка | существующий `idleTimeoutMinutes` | целое 1–60 минут | 5 |
| Показ секрета | новый `secretRevealSeconds` | 5 / 10 / 15 / 30 секунд | 15 |
| Очистка буфера | новый `clipboardClearSeconds` | 10 / 20 / 30 / 60 секунд | 20 |
| Сочетание | существующий `hotkey` | текущие правила parseHotkey | Ctrl+Alt+Space |
| Поле быстрой вставки | новый `quickPasteDefaultField` | secret / login | secret |
| Очистка окружения при выходе | существующий `env-clear-on-exit` | bool | false |

Отсутствие новых ключей сохраняет прежнее поведение. Чтение недопустимых значений не выключает защиту: автоблокировка ограничивается прежним диапазоном, неизвестные перечисления и сроки заменяются безопасными значениями по умолчанию. Неверное сохранённое сочетание показывается как ошибка регистрации; другое сочетание молча не назначается. Только открытие окна не перезаписывает настройки.

Автозапуск использует существующий путь к EXE с `--tray`; системные задания и права администратора не добавляются. Невозможность прочитать состояние Windows показывается как «Недоступно», а не как выключенный флажок. Такие значения не перезаписываются при сохранении остальных параметров.

Для закрытия: hide прячет без немедленной блокировки, lock-hide сначала блокирует и прячет, exit выполняет существующий полноценный выход. Во всех случаях бездействие и сеанс сохраняют свои правила. «Выход» из меню и трея всегда завершает приложение независимо от предпочтения. Если область уведомлений недоступна, крестик блокирует и завершает программу, чтобы не оставлять невидимый недоступный процесс. Настройка применяется после сохранения; закрытие самого диалога настроек не считается закрытием главного окна.

После lock-hide хранилище остаётся закрытым, а экран разблокировки не появляется автоматически: его открывает явное действие «Открыть» или активация иконки трея. Это требует согласовать closeEvent с циклом шлюзов в main; одного вызова hide перед Application::lock недостаточно. Настоящий выход в таком состоянии завершает процесс, а не открывает новый диалог. Запуск с `--tray` при существующем заблокированном хранилище использует то же ожидание явного открытия; первоначальная настройка отсутствующего хранилища остаётся видимой.

## 5. Безопасность и таймеры

Интервал автоблокировки передаётся существующему IdleTimer, без второго таймера. После успешной смены начинается отсчёт нового интервала; продолжает учитываться настоящий пользовательский ввод, а обновления статусов не продлевают сеанс.

Показ секрета использует один существующий таймер карточки. Подпись «Показать на N секунд» и фактическая длительность совпадают. Смена параметра скрывает уже показанный секрет; следующий показ использует новый срок. Потеря фокуса, выбор другой записи, блокировка и повторная проверка сохраняют действующее поведение.

ClipboardGuard остаётся единственным владельцем копирования карточки и панели. При смене срока очищается только текущая собственная публикация; об этом рядом с параметром есть пояснение. Чужой буфер не очищается и старое содержимое не восстанавливается. Новое копирование использует новый срок. Занятый буфер обрабатывается существующими ограниченными повторами. Открытие/отмена настроек ничего в буфер не записывает. Подписи и уведомления берут действующий срок, а не фиксированные 20 секунд.

На странице показаны текущий способ разблокировки и понятные границы Hello/DPAPI. Параметров отключения проверки получателя, повторной проверки записи, защиты истории буфера и блокировки сеанса нет. Эти свойства нельзя выключить подменой предпочтений.

## 6. Быстрая вставка

Редактор сочетания принимает ровно один аккорд по существующим правилам: Ctrl/Alt/Win, при необходимости Shift, и A–Z, 0–9, Space или F1–F11. F12, одиночные клавиши, только Shift и последовательности аккордов отклоняются. Фактическая регистрация показана отдельно от введённого черновика; до сохранения новое сочетание не регистрируется.

Смена использует текущий QuickPaste::changeSequence. При конфликте или ошибке хранения прежняя регистрация сохраняется; окно остаётся открытым и объясняет причину. Одно и то же сочетание не снимается и не регистрируется заново без необходимости. После сохранения статус окна и футер главного окна согласованы.

«Поле по умолчанию» выбирает начальное поле при открытии панели и переходе к другой записи. Для credentials доступен login или secret, для API-токена — secret. При предпочтении login и выборе API-токена используется secret. Для credentials пустой предпочитаемый логин не подменяется паролем молча: пользователь видит выбранное поле и недоступное действие до изменения выбора. Ручной выбор поля действует в текущей операции; в предпочтения не записывается. Обновление поиска с сохранением той же выбранной записи не сбрасывает ручной выбор поля.

Проверки окна, процесса, фокуса и прав всегда включены. Отказ вставки не запускает копирование автоматически, Enter не отправляется. Ограничения SSH, многострочных значений, UIPI и остаточной гонки foreground/SendInput сохраняются.

## 7. Выдача секретов

Показаны пояснения существующих режимов: запуск программы с переменной её окружения и пользовательская переменная Windows. Создание переменной по-прежнему начинается из конкретной записи через EnvExportDialog, с текущей проверкой и предупреждением об открытом хранении в реестре. Настройки не получают значений секретов.

Флажок очистки при выходе использует прежний `env-clear-on-exit`. Отдельная кнопка удаляет только переменные, учтённые TokenBucket, через существующий механизм. Перед удалением есть собственное подтверждение; значения переменных не показываются. При частичном отказе оставшиеся имена сохраняются в учёте и выводится результат, а не общий успех. Предупреждения не управляются флажком уведомлений трея.

Удаление переменных, смена пароля/режима и восстановление копии — отдельные действия, не последствия «Сохранить». При наличии черновика такие действия недоступны с пояснением сначала сохранить либо отменить изменения. У них собственные подтверждения; отмена настроек не обещает отменить уже выполненную отдельную операцию.

## 8. Резервные копии и восстановление — F4

Раздел показывает путь текущего контейнера и существующей `.bak`, наличие, размер и время изменения. Состояния различаются: «Нет копии», «Доступна, содержимое ещё не проверено», «Недоступна». Само наличие файла не считается проверкой AEAD. Содержимое копии и секреты в настройках не раскрываются. Расписание копирования, облако и выбор произвольного каталога не добавляются.

«Восстановить…» работает только с собственной `.bak` при доступном и не занятом хранилище, без неприменённого черновика настроек. Последовательность:

1. Строго прочитать ограниченный по размеру обычный файл через VaultStore; ссылки, reparse-подмены и недопустимые контейнеры отклонить. Снять байтовый снимок кандидата и текущего файла.
2. Запросить подтверждение владельца для режима именно этой копии: пароль копии либо существующий Hello. Пароль мог измениться после её создания. Проверить границы контейнера/KDF, AEAD и полную модель. Результат не подставлять в действующее хранилище до окончания проверки.
3. Показать отдельное подтверждение замены данными копии. Указать её дату, что новые изменения будут заменены и после успеха потребуется разблокировка. Отмена и неверные данные до этой точки не меняют main или .bak.
4. Перепроверить, что файлы и поколение операции не изменились. Сохранить прежний зашифрованный main в уникальный `vault.tb.before-restore-<UTC>-<random>` в том же защищённом каталоге. Использовать существующие FileOps/права владельца и SYSTEM; перечитать и сравнить байты. При невозможности создать проверенную страховочную копию замену не выполнять.
5. Записать проверенный зашифрованный кандидат во временный файл с закрытыми правами, перечитать и сравнить, затем атомарно заменить основной файл. Кандидат `.bak` при восстановлении не перезаписывать. Обычный save с ротацией `.bak` не использовать для этой операции и не ослаблять его проверку verified_.
6. После успеха заблокировать приложение и очистить старые модели/панели; показать обычный экран разблокировки с режимом восстановленного контейнера. Проверенный кандидат не открывает новый сеанс автоматически. Страховочная копия остаётся, её путь сообщается пользователю. Следующие обычные сохранения используют прежнюю политику ротации `.bak`.

Долгие проверки и файловые операции выполняются существующим способом через QtConcurrent/busy, с запретом повторного входа. Пока идёт проверка, блокировка отменяет дальнейшее применение. Непосредственно перед файловой фиксацией поколение проверяется ещё раз. Если блокировка совпала с уже начавшейся атомарной заменой, завершённую замену не выдавать за гарантированно отменённую: приложение остаётся заблокированным, результат файла проверяется, страховочная копия сохраняется, итог сообщается явно. Поздний результат никогда не возвращает Ready.

При отказе записи страховочной копии, временного файла или замены действующий main остаётся прежним. До успешной фиксации нельзя публиковать новый verified_, менять ключ открытого сеанса или принимать модель кандидата. Собственные временные файлы убираются по существующим правилам; действующие main/.bak/страховочная копия не удаляются как временные. Произвольный импорт и восстановление при невозможности открыть основной контейнер остаются вне этого интерфейса.

## 9. Сохранение и ошибки

Хранение предпочтений и операции Windows не образуют общей атомарной транзакции. Интерфейс не обещает такую гарантию. До применения выполняется общая проверка диапазонов и сочетания. Применяются только изменённые значения; неизменённый автозапуск и неподдерживаемые параметры не затрагиваются.

Каждый изменённый параметр сохраняется с проверкой результата. Обычные QSettings-параметры применяются к работающим компонентам только после успешного sync; при отказе возвращается прежнее значение в памяти. Смена сочетания использует существующий собственный откат. Автозапуск считается изменённым только после успешного системного вызова и чтения состояния. При невозможности подтвердить откат показывается отдельная ошибка с фактически известным состоянием, успех не объявляется.

На первой ошибке дальнейшее применение останавливается. Диалог остаётся открытым, называет неудачный параметр и явно сообщает, какие предыдущие изменения уже сохранены. Эти значения перечитываются в новый исходный снимок; неприменённый черновик остаётся редактируемым. «Отмена» после частичного сохранения отменяет только оставшийся черновик; сохранённые изменения не выдаются за откатившиеся. Полное успешное сохранение закрывает диалог. Изменений нет — закрытие без записи и без системных вызовов.

Настройки не содержат секретов, их хешей или данных проверки. Значения и тексты ошибок не интерпретируются как HTML. Метаданные резервных файлов выводятся обычным текстом. Секреты и содержимое контейнеров в журналы не попадают.

## 10. Границы реализации

Новый SettingsDialog отвечает за страницы, черновик, доступность действий и показ результата. Значения предпочтений представлены одним небольшим типизированным снимком с централизованными значениями по умолчанию и проверкой. Используется тот же QSettings; отдельная база, глобальный singleton и универсальный движок транзакций не нужны.

MainWindow соединяет диалог с действующими ClipboardGuard, EntryCard, QuickPaste и IdleTimer. TrayController и EnvOps читают тот же источник настроек. Имеющаяся возможность подставить QSettings в MainWindow расширяется на затронутые настройки, чтобы тесты не записывали пользовательский реестр. Файловое восстановление принадлежит Application/VaultStore, а не обработчику кнопки. Интерфейс не заменяет файлы напрямую.

На Windows все разделы работают в описанном объёме. На других платформах неподдерживаемые Windows-операции показываются недоступными с объяснением; они не заменяются имитацией успеха. Linux-сборка проверяется отдельно при наличии среды, без заявления о неподтверждённом результате.

## 11. Приёмка

- Чистые и прежние настройки дают прежние начальные значения; неправильные сроки не отключают защиту. Простое открытие и отмена не пишут QSettings, реестр, файлы или буфер.
- Изменения сохраняются и подхватываются после повторного открытия и нового запуска; смена темы, уведомлений, сроков и поведения закрытия реально работает. Подписи сроков и футер совпадают с применёнными значениями.
- Ошибка QSettings, конфликт сочетания и отказ автозапуска оставляют проверяемое прежнее состояние затронутого параметра. Частичный результат явно отражён, повтор и отмена не скрывают ошибку.
- Показанный секрет скрывается при смене срока; прежняя собственная публикация очищается при смене срока буфера, чужая сохраняется. После блокировки незавершённое сохранение не запускает выдачу.
- Предпочтение login/secret применяется к допустимым типам; ручной выбор не перезаписывает предпочтение. Все существующие негативные маршруты вставки сохраняются.
- Все три варианта закрытия проверяются отдельно от явного выхода; при отсутствии трея процесс не остаётся скрытым. Блокировка продолжает работать в скрытом состоянии. После lock-hide и запуска `--tray` с заблокированным хранилищем до действия в трее нет видимого окна разблокировки; действие в трее открывает обычную разблокировку, а явный выход действительно завершает процесс.
- Восстановление проверяется на временных контейнерах: правильный/неверный пароль, старый пароль копии, подменённый/повреждённый/слишком большой файл, ошибка страховочной записи, временной записи и замены, изменение main/.bak, повторный вход, отмена и блокировка во время проверки/фиксации. После успеха проверяются штатная разблокировка, точные данные копии, следующий save и пригодность сохранённого прежнего файла для возврата.
- Windows Hello проверяется внедряемым ответом в автоматических тестах; реальная биометрия без отдельного действия владельца пройденной не считается.
- Клавиатура, подписи/accessible names, обе темы, масштаб 100/200% и небольшой экран: все настройки достижимы, нижние кнопки доступны, значения не обрезаются без возможности прочитать их.
- Перед завершением: Release build, полный CTest с проверкой журналов на failed/skipped, независимое ревью и проверка пакета. Сборка помещается в `D:/Sources/gitverse/TokenBucket/dist/TokenBucket/`, основной ZIP — рядом, прежняя сборка сохраняется.

Проверки используют временные настройки, контейнеры, изолированные системные зависимости и вымышленные значения. Настоящие автозапуск, переменные окружения, vault и политика защиты владельца автоматически не меняются. Разрешение на системный буфер относится только к ранее согласованным тестовым окнам.
