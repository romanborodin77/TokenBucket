# Структурированный реестр и новые типы хранения TokenBucket

Дата: 2026-10-24. Статус: написанная спецификация утверждена владельцем ответом «Утверждаю спецификацию»; реализация новых типов не начата. Основание: просьба добавить текстовые файлы по строкам и простые видимые значения, показанный интерактивный макет и команда «продолжение».

## 1. Цель и выбранный подход

Хранить связанные данные проекта как понятный реестр: «Проект → ресурс → раздел → параметры». Например, Oitasc → PostgreSQL VM → Виртуальная машина / PostgreSQL / Проект и сервисы. Использовать нынешние проекты и группы, без отдельной инфраструктурной базы.

Добавить к API-токену, логину/паролю и SSH-ключу два типа: «Простое значение» и «Текстовый файл — строки». Простое значение не обязано быть переменной окружения: это также произвольная однострочная справочная информация. Референс структуры — перенесённые oitasc.txt и orbitrax.txt; в документах, макетах и тестах используются вымышленные значения.

Рекомендуется реестр по ресурсам с просмотром исходного файла рядом. Файловая организация остаётся дополнительным представлением: она сохраняет контекст, но медленнее для поиска рабочего параметра. Плоский список всех строк не выбран основным, поскольку теряет принадлежность параметра ВМ или сервису.

Входят создание, просмотр, изменение, поиск, копирование, безопасная вставка простого значения, импорт TXT с предварительным просмотром и отдельное преобразование существующих записей. Синхронизация с исходными файлами, исполнение команд из TXT, автоматическое обновление с серверов, новые права MCP/API и массовая выдача секретов сюда не входят.

## 2. Подтверждённая исходная модель

База документа: ветка unified-settings на 114af8c с незавершённым этапом A1 настроек. Новые типы ещё отсутствуют. Граф использован для навигации; следующие ограничения подтверждены исходниками:

- src/model/Types.h: EntryType имеет значения 0=ApiToken, 1=Credentials, 2=SshKey; Entry — обычный value-тип.
- src/model/VaultModel.cpp: проверяются типы 0–2, сериализация CBOR v3, чтение v1–v3; неизвестная версия отклоняется. Поиск не просматривает token/password.
- src/model/VaultModel.h: до 10 000 записей, глубина групп до 8, значение до 1 МиБ, открытая модель до 64 МиБ.
- src/platform/QuickPaste.h: поле вставки разрешено только подходящим типам, однострочным непустым значениям без NUL.
- EntryEditDialog, EntryCard, MiniPanel и подписи MainWindow используют ветвления для трёх типов; их необходимо расширить вместе с моделью.
- src/io/Import.* сейчас разбирает CSV и KeePass XML; импорт TXT должен стать проверяемым продуктовым маршрутом.

Этап единых настроек сохраняет свой объём и журнал исполнения. Изменение внутренней модели — отдельный последующий этап, а не незаметное расширение A1. Проверки разработки не обращаются к настоящему vault, Run, буферу и исходным секретам владельца.

## 3. Поведение пяти типов

| Тип | Показ в карточке и списке | Поиск по значению | Копирование и вставка |
| --- | --- | --- | --- |
| API-токен | Скрыт, действующая проверка перед выдачей | Нет | Прежнее поведение |
| Логин и пароль | Логин видим, пароль скрыт | Логин; пароль не ищется | Прежний явный выбор поля |
| SSH-ключ | Закрытый ключ скрыт | Секретные байты не ищутся | Прежний защищённый маршрут; автоматической вставки ключа нет |
| Простое значение | Видно сразу после разблокировки | Да, кроме записей с повторной проверкой | Отдельное копирование; безопасная вставка одной строки |
| Текстовый файл — строки | Номера строк, комментарии, разрешённые видимые строки; остальные скрыты | Только разрешённые видимые строки, кроме записей с повторной проверкой | Отдельная строка; весь файл — отдельное подтверждённое действие |

Все пять типов зашифрованы на диске тем же контейнером. Видимость после разблокировки не означает открытое хранение на диске или доступ ИИ. При блокировке значения и строки удаляются из моделей представления, карточки, поиска, панелей и редактора.

Флаг reverify сохраняется для всех типов. Он имеет приоритет над немаскируемым представлением: в списке и поисковом превью такой записи доступны только обычные метаданные, а значения открываются в выбранной карточке после существующей проверки владельца. Содержимое reverify-записей не используется в глобальном поиске даже после разового показа. Иначе поиск стал бы обходом повторной проверки.

## 4. Простое значение

Поля: обычные title/group/note/tags/expiry/favorite/reverify, необязательное имя параметра, собственно строковое значение и формат отображения text / ip / url. Значение не хранится в token или note. Имя параметра — до 128 печатных символов без управляющих символов; оно не обязано удовлетворять правилам имени переменной окружения. При экспорте в окружение действуют прежние отдельные правила имени.

Строка — до 1 МиБ UTF-8, без NUL, CR, LF и Unicode-разделителей строк/абзацев. Пустая строка разрешена, показывается как «Пусто»; копирование и вставка пустого значения недоступны. Формат text не пытается распознать тип содержимого. Формат ip проверяет настоящий IPv4/IPv6; url проверяет синтаксис абсолютного URL. Выбор text позволяет хранить справочный текст без навязанного формата.

URL никогда не открывается автоматически. Отдельное действие открытия доступно только http/https после явного выбора владельца; file, javascript и другие исполняемые схемы не запускаются. URL с userinfo или потенциальными токенами в query предлагается хранить секретом, не переводится в видимое поле автоматически.

В реестре показываются имя и понятная подпись, значение, тип и действие копирования. Длинное значение отображается ограниченным предпросмотром с доступом к полной строке в карточке и редакторе; обрезка не меняет сохранённые байты значения. Подпись полного имени доступна с клавиатуры.

Переход существующего API-токена, пароля или скрытой строки в простое значение требует отдельного подтверждения «Значение станет видимым после разблокировки и доступным поиску». Предупреждение не выключается настройкой уведомлений. Тип не меняется только потому, что значение похоже на IP или UUID.

## 5. Текстовый файл и строки

Каноническое содержимое — один массив исходных UTF-8-байтов; отдельной редактируемой копии того же текста в строках или параметрах нет. Хранятся имя файла без каталога, признак снимка источника и список номеров строк, которые владелец явно разрешил показывать. Строки, их границы и просмотр строятся из канонических байтов.

Ограничения: до 1 МиБ и 50 000 логических строк. Имя файла — от 1 до 255 символов, без каталогов, управляющих символов и значений «.»/«..». Пустое тело файла допустимо. Некорректный UTF-8, NUL, превышение размера или числа строк отклоняются до изменения модели. UTF-8 BOM, CRLF/LF/CR, пустые строки, комментарии и наличие завершающего перевода строки сохраняются при импорте и неизменённом экспорте. Разделители CRLF считаются одним; завершающий перевод строки даёт последнюю пустую строку в просмотре. Пустой файл или только BOM дают ноль строк.

Показ комментария тоже требует разрешения: комментарий может содержать пароль. По умолчанию все строки скрыты. Предварительный разбор предлагает видимые строки для проверяемых несекретных параметров; владельцу надо подтвердить предложенную классификацию перед её сохранением. Секретные, неизвестные и неоднозначные строки остаются скрытыми. Кнопка отдельного показа использует общий срок показа и действующую проверку владельца.

Редактор различает простой просмотр и реальное изменение. Если тело не менялось, сохранение метаданных не нормализует байты. После редактирования тела устанавливается явно показанный режим окончания строк LF; список разрешённых видимых строк сбрасывается и проверяется заново, чтобы вставленная строка с паролем не унаследовала видимость прежнего номера. Перед сохранением редактор предупреждает об этом сбросе; отмена ничего не меняет. Признак UTF-8 BOM сохраняется.

Снимок исходного TXT неизменяем: корректировка содержимого доступна через «Редактировать копию», с новым UUID. У снимка можно менять название, группу и несекретные метаданные. Модель отклоняет замену тела или снятие признака снимка у той же записи; удаление остаётся отдельным существующим действием.

В карточке файла есть просмотр строк, копирование выбранной строки, разбор в реестр и отдельное копирование/сохранение всего файла. Выбор строки не раскрывает остальные строки. Полное копирование или экспорт файла со скрытыми строками требует существующей проверки владельца, если она назначена записи, и отдельного подтверждения наличия секретов. Обычная кнопка копирования параметра весь файл не выдаёт. Запись файла использует закрытые права и отказ при существующей цели; явная перезапись — отдельное подтверждение.

Текстовый файл целиком не появляется кандидатом автоматической вставки. Поле простого значения может вставляться как один непустой однострочный результат с прежними проверками окна, процесса, фокуса и прав; логически это «Значение», не «Пароль». Enter не отправляется; отказ вставки не запускает автоматическое копирование.

## 6. Импорт TXT и разбор в реестр

Последовательность: выбрать существующую группу ресурса → прочитать ограниченный обычный файл → сохранить временный разбор в памяти → показать исходные строки и предложения → исправить типы/группы → подтвердить → один проверенный save. Пока открыт редактор/предпросмотр, быстрая выдача приостановлена; блокировка закрывает окно и отменяет неприменённый разбор.

Разбор распознаёт NAME=VALUE, необязательный export, парные внешние кавычки и NAME: VALUE с непустым именем. Это текстовый разбор: shell, подстановки переменных, escape-последовательности и команды не выполняются. Непонятная запись сохраняется исходной строкой, не отбрасывается и не получает видимость по догадке. Полный снимок файла создаётся вместе с извлечёнными записями, если владелец подтвердил импорт.

Повторные имена сохраняются отдельными предложениями с номерами строк. Последнее значение не перезаписывает предыдущие автоматически. Для уже существующей записи показываются совпадение или конфликт; выбор по умолчанию — пропустить точное совпадение и создать отдельную версию для отличающегося значения. Замена требует явного выбора.

Пароли, токены, секретные ключи, access key, строки подключения с учётными данными и неоднозначные строки предлагаются защищёнными. Публичные/частные IP, проверенные адреса без учётных данных, версии, имена баз, пользователей и проектные ID предлагаются простыми значениями. Название поля не гарантирует отсутствие секрета; «сделать видимым» подтверждается отдельно.

Группы вида «Виртуальная машина», «PostgreSQL», «Проект и сервисы» — редактируемое предложение по заголовкам исходника. Они не являются обязательной схемой для любого проекта. Неопределённый раздел остаётся в выбранной группе с обозначенным источником.

Предварительный просмотр сообщает число исходных строк, записей, совпадений, конфликтов и пропусков. Ограничение 10 000 записей и глубина 8 проверяются на всём кандидате до записи. Ошибка в любом выбранном элементе оставляет исходное хранилище и модель прежними, окно остаётся открытым с причиной. Частичного импорта с общим сообщением об успехе нет.

## 7. Связь параметров с источником

Общие метаданные записи получают необязательную ссылку на UUID снимка TXT и номер исходной строки. Параметры и секреты ссылаются на один снимок; рабочее значение живёт в собственной записи. Его изменение не переписывает снимок. Карточка явно сообщает «Источник — снимок импорта; рабочее значение могло быть изменено».

Это происхождение данных, а не скрытая двусторонняя синхронизация. Удаление снимка не удаляет рабочие параметры: ссылка показывается как «Источник недоступен». При существующем целевом UUID он обязан указывать на текстовый снимок; номер строки обязан быть допустимым. Самоссылка и ссылка на другой тип отклоняются. Сохранённая отсутствующая цель допустима как уже удалённый источник.

Для сравнения с источником берётся выбранная строка снимка и показывается результат «совпадает / отличается» после той же проверки доступа, что нужна для рабочего значения и строки. Значения или хеши секретов не выводятся в журнал. Менять рабочую запись или источник при одном открытии карточки нельзя.

## 8. Модель и совместимость

Существующие значения EntryType 0–2 сохраняются. Добавляются 3=PlainValue, 4=TextFile. Старые поля секретов сохраняют смысл; новые данные не маскируются под API-токены.

Внутренняя модель переходит на CBOR v4. Читаются v1, v2, v3 и v4; записи старых версий по-прежнему допускают только типы 0–2. У новых полей обязательны корректные типы и ограничения; старые файлы читаются с пустыми новыми полями. Значения type вне 0–4, недопустимые форматы, отрицательные/повторные/выходящие за файл номера видимых строк, неверные ссылки и скрытые несовместимые полезные поля отклоняются транзакционно.

Новые полезные поля:

- PlainValue: строка значения, необязательное имя параметра, код формата text/ip/url.
- TextFile: исходные UTF-8-байты, имя файла, bool снимка источника, список разрешённых видимых номеров строк.
- Общие: необязательные UUID источника и номер строки.

Поля неактивного нового типа пусты; при преобразовании запись не оставляет секрет в старом token/password одновременно с видимым значением. Если прежняя запись содержит несколько непустых полезных полей с неоднозначным назначением, автоматическое преобразование не предлагается: ни одно значение не выбрасывается ради прохождения проверки. Содержимое прежних типов 0–2 читается без новой очистки их старых полей. Служебная классификация и ссылки не хранятся в note, чтобы не смешивать данные и текст пользователя.

Эталонный Qt-писатель и защищённый CborWriter обновляются одновременно; их выход по-прежнему совпадает побайтово. Новые значения и тело файла проходят рабочую сериализацию через существующий защищённый буфер. Само шифрование, пароль/Hello, KDF, контейнер TBVK и политика дампов не заменяются.

Открытие старого хранилища ничего не записывает. Перед первым подтверждённым сохранением старого файла в v4 приложение сообщает о несовместимости с прежним EXE и создаёт уникальную проверенную зашифрованную копию до обновления в том же закрытом каталоге. Отказ резервной записи останавливает переход. Старое приложение отказывает при v4 с существующим сообщением о неподдерживаемой версии и не пересохраняет файл. Возврат к старому EXE возможен с сохранённой старой копией, а не с обещанием прочесть новые типы.

Версию прочитанной модели должен знать владелец сохранения Application; UI не определяет её чтением байтов. Правило копии перед обновлением распространяется на все пути перезаписи основного файла, включая смену пароля/режима и подтверждённый импорт поверх него. Защищённый экспорт v4 тоже несовместим с прежним EXE; об этом сообщает экран экспорта, но локальный старый файл не переписывается ради одного экспорта. Проверка резервной копии, её штатное восстановление из плана B и защищённый импорт контейнера используют тот же обновлённый декодер. Путь восстановления не ослабляется ради v4.

## 9. Уже перенесённые записи владельца

Имеющиеся параметры сейчас представлены API-записями в группах cloud.ru / Реестр. Они не становятся видимыми при обновлении программы автоматически. Предлагается отдельное действие «Структурировать реестр…» с выбранными проектами, предпросмотром предлагаемых ресурсов/разделов и типов.

Преобразуются только выбранные записи. UUID, избранное, теги, срок действия, повторная проверка и пользовательские заметки сохраняются; created сохраняется, modified меняется после подтверждённого изменения. Перенос значения token в PlainValue выполняется точно, без trim или интерпретации; старое поле очищается. Чувствительные и неуверенно распознанные записи сохраняют защищённый тип.

Исходные TXT преобразуются в снимки TextFile только после проверки корректного UTF-8 и точности восстановления исходных байтов из сохранённого текста; при неизвестной точности исходная запись остаётся прежней, а для нового снимка предлагается выбрать исходный файл. SSH-пары остаются прежними побайтовыми записями. Их повторный импорт или изменение прав исходников не являются частью этого действия.

До фактической миграции создаётся проверенная зашифрованная страховочная копия. Кандидат целиком проверяется до сохранения; отказ возвращает прежнюю модель. После успеха выполняется повторное открытие/проверка данных. Разрешение на прежний импорт само по себе не разрешает автоматически менять видимость существующих секретов. Этот документ не изменяет живое хранилище.

## 10. Ответственность компонентов и порядок работ

| Участок | Обязанность |
| --- | --- |
| Types / VaultModel | Два полезных типа, ограничения, поиск видимых значений, происхождение данных |
| VaultModel / CborWriter / Application | v4, чтение старых файлов, защищённая запись и сохранение копии перед обновлением |
| TXT parser / Import | Чистый разбор без побочных действий, снимок, предложения, конфликты и кандидат миграции |
| EntryEditDialog | Пять типов, адаптация к полям, явная смена видимости, байты файла и классификация строк |
| EntryCard / MainWindow | Реестр по существующим группам, видимость, строки, источник и отдельные действия |
| QuickPaste / MiniPanel / EnvExportDialog | Явная поддержка PlainValue, исключение целого TextFile, прежние проверки выдачи |
| Application / VaultStore | Атомарное применение, отмена/блокировка, восстановление копий с обновлённым декодером |

Сначала довести текущий утверждённый этап настроек до согласованной безопасной точки с зелёными проверками и записью в его журнале. Затем реализовать новые типы отдельными проверяемыми задачами модели, UI и импорта; только после них выполнять преобразование данных владельца. Реальная миграция остаётся действием владельца в готовом интерфейсе.

Новых сторонних пакетов, общего движка схем и отдельного сервера реестра не требуется. Для проверки IP используется QHostAddress из уже установленного QtNetwork; модуль добавляется к связям сборки и проверяется в пакете. Старые ветвления вида «иначе SSH» или «иначе пароль» заменяются явной обработкой всех пяти типов; неизвестный тип не получает доступ к секретному полю по умолчанию.

## 11. Приёмка

1. Старые v1–v3 читаются без изменения значений; v4 сохраняет каждый тип. Эталонная и защищённая сериализация совпадают, неверные версии/поля/строки/ссылки отклоняются без частичной модели.
2. Все пять форм создают и редактируют реальные временные записи; отмена/крестик/блокировка не сохраняют черновик. Новые формы компактны, полное значение доступно при узком окне и масштабировании.
3. Простые значения видны после разблокировки и ищутся; токены, пароли, скрытые строки и reverify-значения глобальным поиском не обнаруживаются. Переход секрета к видимому виду требует отдельного подтверждения.
4. TXT: BOM, LF/CRLF/CR, последняя пустая строка, комментарии, кавычки, повторные имена, неизвестные строки, пустой файл и файл с секретами. Импорт/неизменённый экспорт дают точные исходные байты.
5. Изменение тела сбрасывает разрешённые видимые строки; снимок не изменяется на месте. Редактирование метаданных сохраняет тело точно. Неверный UTF-8/NUL/размер/число строк отклоняются заранее.
6. Разбор и миграция: точные совпадения, конфликты, явная замена, пропуски, переполнение лимитов, ошибка записи, повторная попытка, отмена и блокировка. Источник/рабочее значение различимы; удалённый источник не уничтожает данные.
7. Предшествующие записи, SSH-байты, теги, сроки и повторная проверка сохраняются. Нет переноса секретных значений в поисковые заметки, уведомления и журналы.
8. Простое значение вставляется только в согласованное тестовое окно; пустое/многострочное/недопустимое значение и TextFile не отправляются. Нет Enter и автоматического копирования после отказа.
9. Переход на v4 создаёт пригодную старому EXE копию; отказ её создания или save сохраняет прежний основной файл. Восстановление v3/v4 проходит обычную полную проверку. Повторное сохранение v4 не удаляет уникальную копию до обновления.
10. Светлая/тёмная тема, клавиатура, чтение подписей и узкий экран; Release build, весь CTest, проверка failed/skipped, независимый обзор ветки и проверка пакета. Тесты используют временные vault/настройки и вымышленные данные; реальный Hello и физический DPI не считаются проверенными без отдельной приёмки.

Поставка сохраняет постоянные пути dist/TokenBucket и TokenBucket-windows-x64.zip с проверкой предыдущего пакета. До окончания проверок текущая сборка владельца не заменяется.

## 12. Следующее согласование

Рассмотрение и утверждение этой написанной спецификации предшествуют отдельному плану реализации. После его рассмотрения сохраняется выбранный способ исполнения — последовательно в текущем чате с итоговым независимым обзором. Открытые секреты, публикация, удалённый push и предоставление доступа внешним ИИ этим документом не разрешаются.
