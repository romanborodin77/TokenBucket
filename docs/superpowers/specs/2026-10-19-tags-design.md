# Теги записей TokenBucket — дизайн

Дата: 2026-10-19. Статус: на ревью пользователя.
Родительская спецификация: `2026-10-18-tokenbucket-design.md` (v1). Этот документ расширяет модель данных; изменения затрагивают формат CBOR и общий код, платформенно-специфичного кода не требуют.

## 1. Цель и объём

Теги для записей: ввод в редакторе (через запятую, с автодополнением), поиск по тегам, фильтрация списка кликабельными «чипами» тегов, переименование тега во всём хранилище и удаление тега со всех записей. Поведение одинаково на Windows и Linux — платформенного кода нет.

Вне объёма: цвета и описания тегов, теги на группах/проектах, экспорт по тегу, теги в мини-панели быстрой вставки.

## 2. Модель данных

- `model::Entry` дополняется полем `QStringList tags`.
- Нормализация значений (единая для ввода из UI и импорта): у каждого тега убираются пробелы по краям; пустые отбрасываются; дедупликация внутри записи без учёта регистра (сохраняется первое написание).
- Лимиты: не более 16 тегов на запись; длина тега 1–32 символа (UTF-8). Превышение — ошибка `setEntry`: «Тегов больше 16.» / «Тег длиннее 32 символов.»
- `created`/`modified` записи при нормализации не меняются; обычное сохранение записи обновляет `modified`, как и раньше.

## 3. Формат CBOR

- Версия содержимого `"v"` поднимается с 1 до 2. В каждой записи появляется массив строк `"tags"`.
- `fromCbor` принимает v1 (теги считаются пустыми) и v2; иные версии — «Неподдерживаемая версия данных.» (Bad), как раньше.
- Разбор v2: отсутствие ключа `"tags"` считается пустым списком; ключ не массив или элемент не строка — «Хранилище повреждено (теги).» (Bad); нарушение лимитов в разобранном файле — «Хранилище повреждено (теги).» (Bad): наше приложение лимиты соблюдает, нарушение означает постороннее изменение.
- Контейнер (магия, режимы, Argon2id) не меняется — только содержимое. Экспорт/импорт и режим Hello работают без изменений.

## 4. Новые методы VaultModel

- `QStringList allTags() const` — уникальные теги по всем записям, сортировка без учёта регистра.
- `QString renameTag(const QString& from, const QString& to)` — переименование во всех записях с нормализацией `to` и слиянием дубликатов, возникающих после переименования. Ошибки: «Тег не найден.», «Имя тега пустое.» (после нормализации), «Тег длиннее 32 символов.» (если новое имя слишком длинное).
- `QString removeTag(const QString& tag)` — удаляет тег со всех записей; «Тег не найден.», если тега нет.
- Обе операции меняют только теги записей; `modified` записей не обновляется (содержимое записи не менялось).
- Поиск: тег входит в поля поиска (без учёта регистра).

## 5. Интерфейс

- **Редактор записи**: строка «&Теги:» (`entryTags`) на форме общих полей — видна для всех трёх типов. Ввод через запятую; `QCompleter` по `allTags()` хранилища, дополнение применяется к последнему незавершённому тегу после запятой. Валидация — существующим механизмом `accept()` через пробный `setEntry` (нормализация и лимиты в модели), ошибки показываются в `entryError`.
- **Панель чипов** над списком записей (контейнер `tagBar`): по чипу-кнопке (`QToolButton`, checkable) на каждый тег `allTags()`, подсказка «Записей: N». Клик — включение/выключение фильтра; несколько выбранных чипов = условие И (запись должна иметь все отмеченные теги). Панель показывает теги всего хранилища независимо от выбранной группы и поиска.
- **Контекстное меню чипа**: «Переименовать тег…» (диалог с предзаполненным именем), «Удалить тег…» (подтверждение). Обе операции — через `commit()` с откатом и сообщением об ошибке.
- **Совместимость фильтров**: теговый фильтр (И) применяется вместе с текстовым поиском, фильтром по типу и сортировкой.
- Чипы и их меню — общий код, работают на обеих платформах.

## 6. Совместимость

- Приложение с тегами читает старые хранилища v1 и пересохраняет их как v2 при первой записи.
- Предыдущие версии приложения не откроют v2 («Неподдерживаемая версия данных»). Понижение версии не поддерживается; путь назад — защищённый экспорт не помогает (внутри тот же CBOR), поэтому решение о переходе принимает пользователь осознанно, потеря доступа к старой версии допустима в рамках локального приложения.

## 7. Тесты

`test_model`:
- roundtrip v2 с unicode-тегами, порядок тегов сохраняется;
- разбор v1-документа (собирается тестом вручную) — теги пустые, статус Ok;
- нормализация: trim, дедупликация регистра, лимиты 16 тегов и 32 символа — тексты ошибок;
- `renameTag`: переименование везде, слияние дубликатов, «Тег не найден.», пустое имя;
- `removeTag`: удаление из всех записей, «Тег не найден.»;
- поиск по тегу находит запись, по части тега тоже.

`test_ui`:
- поле `entryTags`: теги записи сохраняются и открываются повторно;
- панель `tagBar`: после добавления записи с тегами появляются чипы; клик фильтрует список, повторный клик возвращает;
- теговый фильтр вместе с фильтром по типу;
- чипы не зависят от выбранной группы.

Переименование/удаление тега через контекстное меню чипа: на уровне модели покрыто `test_model`; UI-меню — ручная проверка владельцем (финальная матрица), автоматический прогон контекстных меню не требуется.

## 8. План реализации

Отдельный план задач по TDD (writing-plans): failing-тесты `test_model` → реализация модели и формата → failing-тесты `test_ui` → редактор и чипы → полный CTest → обновление дистрибутива. Контейнер и платформенные изменения нет.
