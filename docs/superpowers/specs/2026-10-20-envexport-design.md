# Выдача токенов в переменные окружения Windows — дизайн

Дата: 2026-10-20. Статус: реализуется по поручению пользователя («также реализовать функцию передать токены в переменные окружения Windows (постоянные/временные)»); развилки решений принял исполнитель по явной делегации пользователя.

Родительская спецификация: `2026-10-18-tokenbucket-design.md`. Фича только для Windows; на Linux пункты меню не показываются.

## 1. Цель

Выдать секрет записи (API-токен или пароль учётной записи) как переменную окружения:
- **временно** — запустить выбранное приложение с переменной в его среде (секрет живёт только в среде запущенного процесса и его потомков, нигде не сохраняется);
- **постоянно** — пользовательская переменная окружения Windows (HKCU\Environment + WM_SETTINGCHANGE).

## 2. Решения и границы (принятые развилки)

- «Временно» = запуск процесса с окружением, а не `set` в чужой сессии: изменить среду уже запущенных процессов средствами Win32 нельзя; запуск с env — единственный честный временный способ без персистентности.
- «Постоянно» = только пользовательские переменные (HKCU\Environment). Системные (HKLM) не трогаем: требуют повышения прав и расширяют доступ к секрету на всех пользователей.
- Значение пишется как REG_SZ (не EXPAND_SZ): секрет с символами `%` не должен «расширяться» при чтении.
- Имя переменной: `[A-Za-z_][A-Za-z0-9_]*`, до 64 символов, вводится вручную (дефолт — пусто).
- Секрет: однострочный (символ NUL и переводы строк `\r`/`\n` запрещены — как для быстрой вставки); типы ApiToken (token) и Credentials (password); SSH-ключи — нет (многострочные).
- Выдача — это выдача секрета: обязательна повторная проверка (`authorize()`), для записей с `reverify`.
- Постоянная запись сопровождается явным предупреждением: «Значение будет храниться в реестре в открытом виде и будет доступно любому процессу от вашего имени. Новые процессы увидят переменную после перезапуска оболочки/проводника или выхода из системы.» Подтверждение — Yes/No (default No).
- Учёт установленных нами переменных: список ИМЁН (без значений) в QSettings `env-exported`; пункт удаления: выбираешь имя → RegDeleteKeyValue + WM_SETTINGCHANGE. Значения в списке не хранятся.

## 3. Компоненты

- `src/platform/EnvOps.h` + `src/platform/envops_win.cpp` (только WIN32 в CMake):
  - `namespace tb::platform::envops`:
  - `bool validName(const QString&)` — проверка имени.
  - `QString startWithVariable(const QString& program, const QString& arguments, const QString& name, const QString& value, QString* err)` — CreateProcessW с объединённым блоком окружения (GetEnvironmentStringsW + VAR=value); возвращает ошибку или пустую строку. Запуск через `cmd.exe /c program args` не используется: прямой запуск с параметрами как строкой.
  - `bool setUserVariable(const QString& name, const QString& value, QString* err)` — RegSetValueExW(HKCU\Environment, REG_SZ) + SendMessageTimeoutW(HWND_BROADCAST, WM_SETTINGCHANGE, «Environment»).
  - `bool deleteKnownUserVariable(const QString& name, QString* err)` — RegDeleteKeyValueW + broadcast.
  - `QStringList exportedNames()` / `void rememberExported(const QString& name)` / `void forgetExported(const QString& name)` — QSettings («TokenBucket»/«TokenBucket», ключ `env-exported`, список через `,` — имена не содержат запятых по валидации).
- UI (MainWindow, меню «Записи» + контекстное меню списка, только WIN32):
  - «В переменную окружения…» — доступно при выбранной записи подходящего типа. Диалог `EnvExportDialog` (src/ui/EnvExportDialog.h/.cpp): имя переменной (валидация), режим (два радио: «Запустить приложение с переменной (временно)» / «Пользовательская переменная Windows (постоянно)»), для временного — путь к программе (обзор) и аргументы; для постоянного — предупреждение. `accept()` валидирует.
  - Временный режим после диалога: authorize → startWithVariable → сообщение об успехе/ошибке.
  - Постоянный: authorize → подтверждение предупреждения → setUserVariable → rememberExported → сообщение «Переменная установлена…».
  - «Удалить переменные TokenBucket…» (Настройки, WIN32): выбор из exportedNames (если пусто — сообщение) → подтверждение → deleteKnownUserVariable + forgetExported.

## 4. Тесты (tests/test_env_win.cpp, нативная windows-платформа)

- validName: корректные/некорректные имена.
- startWithVariable: запустить `%ComSpec% /c echo(%TB_TEST_VAR% > tmpfile` с переменной → файл содержит значение; очистка tmpfile.
- setUserVariable/deleteKnownUserVariable/remember: запись переменной `TOKENBUCKET_TEST_ENV` → чтение RegGetValueW совпадает → удаление → чтение даёт отсутствие; exportedNames содержит имя до forget и не содержит после.
- EnvExportDialog: валидация имени и обязательности программы во временном режиме.

Реестр и файловая система затрагиваются только тестовой переменной `TOKENBUCKET_TEST_ENV`, очищаемой тестом.

## 5. Ограничения (зафиксировано честно)

- Постоянная переменная видна новым процессам только после перезапуска оболочки — ограничение Windows (WM_SETTINGCHANGE), о чём UI сообщает.
- Изменить среду уже работающих процессов невозможно — не предлагаем.
- Значение в реестре не защищено — предупреждение обязательное; рекомендованный режим в диалоге первый (временный).
