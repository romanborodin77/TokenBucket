# F1–F3: параметры генератора, массовые действия, сохранённые представления

Дата: 2026-10-25. Статус: дизайн F1–F2 утверждён владельцем в чате; для F3 выбрано хранение в зашифрованном хранилище (CBOR v5). Письменная спецификация ждёт рассмотрения. Основание: утверждённые 2026-10-23 функции F1–F3 предложения [улучшений](2026-10-22-tokenbucket-improvements-proposal.md); F4/F5 уже выполнены в единых настройках.

## 1. Цель и границы

Три независимые возможности управления, без изменения криптографии, контейнера TBVK, KDF и способов разблокировки. Новых сторонних пакетов нет. Linux не входит (отложен до явной команды).

## 2. F1 — параметры генератора пароля

- Рядом с существующей кнопкой «Сгенерировать» (`generatePassword`) — кнопка меню параметров: длина 8–128 (по умолчанию 24), группы «A–Z», «a–z», «0–9», «Символы» (по умолчанию все включены), «Исключать похожие знаки» (0/O, 1/l/I; включено).
- Чистая функция `tb::crypto::generatePassword(const GeneratorOptions&)` → QString; случайность — только `randombytes_uniform` (libsodium). В результате есть минимум один знак каждой выбранной группы: сначала по одному знаку из каждой группы, остальное из общего алфавита, затем перемешивание Фишера–Йетса тем же RNG.
- Ни одной группы не выбрано или длина меньше числа выбранных групп → генерация недоступна, причина показана рядом. Символы: `#!%+=-_@$*?.` (без кавычек, пробела и обратной косой черты).
- Параметры — не секрет: хранятся в существующих настройках (`generator/length`, `generator/groups`, `generator/excludeSimilar`) через Preferences с валидацией; неверные сохранённые значения заменяются значениями по умолчанию.

## 3. F2 — массовые действия

- Список записей переходит на ExtendedSelection (Ctrl/Shift). Одна выбранная запись — прежнее поведение. При двух и более карточка показывает «Выбрано: N записей» и не показывает значения; копирование/вставка/показ секрета недоступны.
- Действия (меню «Записи» и контекстное меню списка): «Переместить в группу…» (выбор существующего проекта/группы), «Добавить тег…», «Снять тег…» (список тегов выбранных записей), «Удалить N записей…».
- Удаление: подтверждение с числом записей, по умолчанию «Нет». Если среди выбранных есть записи с повторной проверкой — одна проверка владельца (VerifyDialog) до подтверждения. Удаление одной записи остаётся прежним.
- Каждое действие — одна мутация через существующий `commit()`: проверка всех записей на копии модели, одно сохранение, полный откат при любой ошибке (лимиты тегов, неизменяемость снимка источника — перемещение и теги снимка разрешены, тело не меняется). Удаление снимка, на который ссылаются рабочие записи, допустимо как и сейчас (ссылка показывается как «Источник недоступен»).
- Перед действием фиксируются UUID выбранных записей и поколение; после диалогов изменение поколения или исчезновение записи отменяет действие с сообщением. Действие на старом файле v1–v4 проходит существующее согласие на обновление формата.

## 4. F3 — сохранённые представления (CBOR v5)

- Представление: имя (1–64 печатных символа, уникально без учёта регистра), раздел библиотеки (Все/Избранное/Истекают), группа (UUID или пусто), тип (−1 = все, 0–4), срок (0–2), сортировка (0–1), теги-чипы (нормализованные, до 16), текст поиска (до 256 символов). До 50 представлений.
- Хранятся внутри зашифрованной модели: корень v5 = `v`, `nodes`, `entries`, `views` (массив карт с ключами `name`, `lib`, `group`, `type`, `exp`, `sort`, `tags`, `q` в этом порядке). Читаются v1–v5; у v1–v4 корень строго из трёх ключей, у v5 — из четырёх. Неверный тип/лимит/дубликат имени → транзакционный отказ «Хранилище повреждено (представления).». Эталонный Qt-писатель и защищённый CborWriter обновляются вместе, побайтовое совпадение сохраняется.
- Переход v4→v5 использует существующий механизм: `schemaUpgradeRequired()` сравнивает с текущей версией писателя (5), согласие привязано к поколению, перед первой записью — уникальная проверенная копия `vault.tb.before-upgrade-*`. Сообщения «v4» в согласии и экспорте заменяются текущей версией. Прежний EXE отказывает при v5 существующим сообщением о неподдерживаемой версии.
- UI: под кнопками библиотеки — список «Представления» и кнопка «Сохранить текущее…»; контекстное меню представления: «Переименовать…», «Обновить из текущего», «Удалить». Применение выставляет фильтры; удалённая группа сбрасывается с пояснением в строке состояния, отсутствующие теги не применяются. Изменение представлений — мутация модели через `commit()`. При блокировке список очищается вместе с моделью.

## 5. Ответственность компонентов

| Участок | Изменение |
| --- | --- |
| vault/Crypto или новый vault/PasswordGenerator | Чистая функция генерации |
| app/Preferences | Параметры генератора |
| ui/EntryEditDialog | Меню параметров генератора |
| model/Types, VaultModel, vault/CborWriter | SavedView, лимиты, CBOR v5, чтение v1–v5 |
| app/Application | Версия писателя 5 в правилах согласия |
| ui/MainWindow, EntryCard | Множественный выбор, массовые действия, панель представлений |

## 6. Приёмка

1. Генератор: длины 8 и 128, каждая комбинация групп, «исключать похожие», наличие каждой выбранной группы в 1 000 генерациях, отказ пустого набора, сохранение и восстановление параметров, неверные сохранённые значения.
2. Массовые действия: перемещение/добавление/снятие тега/удаление на 2+ записях, отмена, превышение лимита тегов откатывает всё, отказ сохранения откатывает всё, блокировка во время диалога, reverify при удалении (отмена и подтверждение), карточка без значений при множественном выборе.
3. Представления: roundtrip v5, чтение v1–v4 без представлений, отказ битых `views`, golden-совпадение писателей, переход v4→v5 с согласием и копией, применение/переименование/удаление, удалённая группа и тег, очистка при блокировке.
4. Полный CTest без failed/skipped (разрешённый режим буфера), Release build, обе темы и 420×480 для новых элементов, локальная поставка в dist с сохранением прежней сборки.

## 7. Не входит

Синхронизация представлений между хранилищами, массовое изменение типов/секретов/сроков, генератор парольных фраз, изменение генератора вне редактора записи.
