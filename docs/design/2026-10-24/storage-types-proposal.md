# Типы хранения и реестр ресурсов — проект дизайна

Статус: макет для рассмотрения владельцем, 2026-10-24. Продуктовые изменения новых типов ещё не начаты.

## Намерение

Дополнить API-токен, логин/пароль и SSH-ключ двумя типами: простое значение без маскирования и текстовый файл с просмотром строк. Структуру построить по недавно перенесённым oitasc.txt и orbitrax.txt: IP, пользователи, параметры PostgreSQL, адреса приложений, реестров и резервных копий. В макете используются только вымышленные значения.

## Рассмотренные варианты

- Рекомендуется «Проект → ресурс → раздел → параметры»: дерево существующих групп, компактная таблица и карточка выбранной записи. Связанные данные ВМ и сервиса видны рядом.
- Список файлов с построчным просмотром сохраняет привычный исходник, но поиск рабочего параметра медленнее. Предлагается дополнительным представлением источника.
- Плоский список всех параметров проще, но при росте числа записей теряет контекст ресурса. Для основного экрана не выбран.

## Два новых типа

**Простое значение:** название, стабильное имя параметра, одно строковое значение, существующая группа ресурса, необязательная заметка. Формат «текст/IP/URL» помогает отображению и валидации, не превращает значение в отдельную модель хранения. Значение видно сразу после разблокировки, участвует в поиске, копируется отдельно; кнопки раскрытия нет. Произвольная строка допустима, это не только переменная окружения.

**Текстовый файл — строки:** UTF-8, порядок строк, пустые строки и комментарии сохраняются. Просмотр с номерами строк и состоянием видимости каждой строки; полный файл не раскрывается в поисковом превью. Пароли, токены, строки подключения с учётными данными и неопознанные строки остаются скрытыми. Разбор предлагает именованные записи и целевые группы; классификация проверяется владельцем перед переносом. Отдельное копирование полного файла с секретами требует действующей проверки владельца и подтверждения.

Все пять типов зашифрованы в одном хранилище. «Простое» означает отсутствие маски после разблокировки. Автоблокировка, очистка собственного буфера и проверка получателя продолжают действовать.

## Связь с перенесёнными данными

Исходный TXT — сохранённый снимок импорта. Реестр — отдельные рабочие записи с указанием источника. Изменение параметра не переписывает исходный снимок; расхождение обозначается явно. Повторный разбор показывает совпадения и конфликты, не перезаписывает существующие значения молча. Массовое преобразование имеющихся 40 параметров выполняется отдельным подтверждённым действием.

На этапе реализации нельзя автоматически сделать публичными неизвестные поля или URL с паролями. Переход существующего секрета в простое значение требует отдельного подтверждения. Само наличие нового типа не расширяет разрешения будущего MCP/API.

## Взаимодействия макета

Реестр, выбор Oitasc/Orbitrax, поиск открытых значений, карточка параметра, файл по строкам, предварительная классификация импорта и форма пяти типов. Форма адаптируется к типу без большого пустого пространства. Кнопки копирования не обращаются к системному буферу; сохранение меняет только демонстрационные записи.

Проверены браузерные взаимодействия, светлая/тёмная тема, ширины 320/736/1024 и доступность классификации/кнопки сохранения на узком экране. Ошибок JavaScript в проверенном маршруте нет.

## Следующий этап после согласования

Написанная спецификация и план миграции модели, сериализации, импортов, редактора, карточки, поиска и быстрой вставки. Сохранить чтение старых хранилищ; неподдерживаемая версия должна давать явный отказ старому приложению. Работы единых настроек остаются в своём плане; их контрольная точка записана в соответствующем журнале.
