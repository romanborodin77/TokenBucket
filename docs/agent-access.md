# Доступ локального агента к TokenBucket

Для SSH разблокируйте TokenBucket и откройте «Настройки → Безопасность». Отметьте «Разрешить команды SSH через MCP» и нажмите «Сохранить». Настройка действует сразу и сохраняется после перезапуска. MCP-клиент запускает `TokenBucket-agent.exe --mcp` из каталога Windows-сборки как сервер stdio. CLI и MCP используют один локальный канал и одни диалоги согласия.

Для поиска любых записей по названию и чтения их полей запустите `TokenBucket.exe --agent-access` и разблокируйте хранилище. Флаг общего доступа действует до выхода из приложения.

## Подключение MCP

Поддерживаются MCP `2026-07-28` с `server/discover` и `2025-11-25` с `initialize`. Сервер публикует четыре инструмента. У каждого вызова действуют текущие разрешения TokenBucket.

- `tokenbucket_find` доступен с `--agent-access`. Принимает `title` и после согласия возвращает ID, название и тип одной записи.
- `tokenbucket_read` доступен с `--agent-access`. Принимает `id`, `field` и номер `line` для видимой строки. После согласия и проверки владельца инструмент возвращает JSON с одним значением base64 в текстовом блоке MCP. При отказе или заблокированном хранилище MCP помечает ответ `isError: true`.
- `tokenbucket_find_ssh` доступен при включённом MCP SSH или с `--agent-access`. Принимает `machine` и необязательные `user` и `port`. После согласия инструмент возвращает кандидатов SSH с подходящими привязками.
- `tokenbucket_ssh_exec` выполняет одну команду на выбранной машине после согласия и проверки владельца. Включите SSH-команды в настройках TokenBucket.

Для Codex добавьте в локальный `config.toml` следующую секцию. Укажите абсолютный путь к распакованному помощнику. Тайм-аут оставляет время на подтверждение в окне TokenBucket. [Настройка MCP в Codex](https://learn.chatgpt.com/docs/extend/mcp?surface=cli).

```toml
[mcp_servers.tokenbucket]
command = 'D:\Sources\gitverse\TokenBucket\dist\TokenBucket\TokenBucket-agent.exe'
args = ["--mcp"]
tool_timeout_sec = 120
```

Для Claude Code зарегистрируйте локальный сервер и проверьте его в `/mcp`. [Настройка MCP в Claude Code](https://code.claude.com/docs/en/mcp#option-3-add-a-local-stdio-server).

```powershell
claude mcp add --transport stdio tokenbucket -- 'D:\Sources\gitverse\TokenBucket\dist\TokenBucket\TokenBucket-agent.exe' --mcp
```

Рабочий сеанс MCP принимает UTF-8 JSON-RPC, по одному сообщению на строку, размер входного сообщения до 64 КиБ. Закрытие stdin и отмена активного запроса закрывают его соединение с TokenBucket. [Транспорт stdio](https://modelcontextprotocol.io/specification/2026-07-28/basic/transports/stdio), [инструменты MCP](https://modelcontextprotocol.io/specification/2026-07-28/server/tools), [рукопожатие MCP 2025-11-25](https://modelcontextprotocol.io/specification/2025-11-25/basic/lifecycle).

## Выбор SSH-ключа по машине

Откройте запись SSH и нажмите «Изменить». В таблице «Подключения этого ключа» нажмите «Добавить», введите адрес и при необходимости задайте псевдоним, пользователя и порт. Новая строка получает порт 22. Кнопка «Убрать» удаляет строку при сохранении записи. Сохранённые подключения видны в карточке. Поиск приложения находит ключ по псевдониму или адресу.

Одна запись SSH может хранить до 16 машин. Каждая привязка содержит адрес, порт, необязательный псевдоним и имя пользователя. Несколько ключей могут ссылаться на одну машину. Указывайте ASCII или Punycode для DNS-имени и буквальный адрес для IP. Для IPv6 указывайте адрес без идентификатора зоны. Поиск проверяет точное совпадение псевдонима или адреса без учёта регистра. Имя SSH-пользователя учитывает регистр. Адрес, пользователь и порт должны совпасть в одной привязке. Привязка записывает выбор владельца хранилища. Подлинность SSH-хоста по-прежнему проверяет SSH-клиент.

Передайте `tokenbucket_find_ssh` аргументы `{"machine":"build-lab","user":"deploy","port":2222}`. Прямой CLI принимает запрос `{"v":1,"op":"find_ssh","machine":"build-lab","user":"deploy","port":2222}`. Ответ `entries` содержит ID, название и тип ключа и массив `targets` только с подходящими привязками.

## Выполнение SSH-команды

По умолчанию исполнение выключено. Включите его в разделе «Настройки → Безопасность». В Windows должен быть установлен системный OpenSSH Client. Адрес и порт выбранной привязки должны иметь заранее проверенный ключ хоста в `%USERPROFILE%\.ssh\known_hosts`.

Совместимый запуск с `--agent-access --ssh-exec` включает SSH на текущий сеанс, когда пользователь ещё не сохранял настройку. Сохранённое выключение имеет приоритет над флагами. Выключение в настройках отменяет ожидающее подтверждение и останавливает активный локальный SSH-клиент.

Выберите ID записи и подходящее подключение из результата поиска. Для исполнения нужны сохранённые имя SSH-пользователя и порт. Если имя в привязке пустое, впишите его в редакторе записи. Пример аргументов `tokenbucket_ssh_exec` для проверки имени хоста.

```json
{
  "id": "01234567-89ab-4def-8123-456789abcdef",
  "machine": "build-lab",
  "user": "deploy",
  "port": 2222,
  "command": "hostname",
  "timeoutSeconds": 15
}
```

Для прямого CLI добавьте `"v":1` и `"op":"ssh_exec"`. Команда передаётся оболочке удалённого SSH-сервера одной печатной строкой до 1024 байт UTF-8. В диалоге TokenBucket проверьте ID записи, фактический хост, пользователя, порт и команду. Нажатие «Да» открывает проверку мастер-паролем или Windows Hello. Согласие и проверка обязательны для каждого запуска. `timeoutSeconds` задаёт время исполнения от 1 до 30 секунд, по умолчанию 15 секунд. На согласие и проверку отводится до 60 секунд.

Ответ включает `exitCode`, `stdout` и `stderr`. При ненулевом коде он помечен `isError: true` и содержит `error: "remote_exit"`. Код 255 OpenSSH также использует при ошибках соединения. Если причину нельзя определить по локальной диагностике, инструмент возвращает `ssh_status_unknown` и сохраняет доступный вывод. Общий предел stdout и stderr составляет 64 КиБ до декодирования в UTF-8.

Ключ загружается системным OpenSSH из временного файла с доступом для владельца Windows и SYSTEM. Для зашифрованного ключа сохранённая парольная фраза передаётся локальному дочернему процессу по одноразовому каналу. Поддерживаются фразы до 1023 байт UTF-8 без NUL и переводов строк. MCP получает результат команды. Временный файл удаляется после исполнения, отмены или ошибки. При аварийном завершении приложение проверяет собственные оставшиеся временные каталоги при следующем запуске.

Отмена, обрыв соединения и блокировка хранилища останавливают локальный SSH-клиент. Удалённый сервер мог уже начать команду, поэтому повторный запуск требует отдельного решения владельца.

## Поиск и чтение через прямой CLI

`TokenBucket-agent.exe` без аргументов читает один JSON-запрос из stdin до завершения потока и возвращает один JSON-ответ в stdout. Пример для PowerShell 7. Сначала передайте точное название записи. Владелец разрешает передачу её названия, типа и ID. При нескольких совпадениях назначьте записям различные названия.

```powershell
$helper = Join-Path $PWD 'TokenBucket-agent.exe'
$find = @{ v = 1; op = 'find'; title = 'Deploy SSH' } | ConvertTo-Json -Compress
$match = $find | & $helper | ConvertFrom-Json
```

Затем используйте возвращённый UUID и имя одного поля. Нажатие «Да» открывает проверку мастер-паролем или Windows Hello даже для записи без настроенной повторной проверки. Каждый ключ и парольная фраза запрашиваются отдельно.

```powershell
if ($match.ok) {
    $read = @{ v = 1; op = 'read'; id = $match.entry.id; field = 'sshPrivate' } | ConvertTo-Json -Compress
    $result = $read | & $helper | ConvertFrom-Json
    if ($result.ok) { $keyBytes = [Convert]::FromBase64String($result.value) }
}
```

Чтобы получить открытый ключ, передайте `field = 'sshPublic'`. Для парольной фразы используйте `field = 'sshPassphrase'`.

| Тип в ответе поиска | Поля для чтения |
| --- | --- |
| `apiToken` | `token` |
| `credentials` | `login`, `password` |
| `sshKey` | `sshPrivate`, `sshPublic`, `sshPassphrase` |
| `plainValue` | `plainValue` |
| `textFile` | `textLine` и обязательный номер видимой строки `line`, начиная с `1` |

Для `textLine` используйте номер из редактора текстового файла. Строка должна быть отмечена как видимая. Например, `{"v":1,"op":"read","id":"01234567-89ab-4def-8123-456789abcdef","field":"textLine","line":2}` возвращает сохранённые UTF-8 байты строки без BOM файла и без перевода строки. Для SSH-ключей ответ сохраняет исходные байты, включая окончания строк. Другие поля возвращаются в UTF-8. Пустое поле может вернуть пустую строку base64.

## Формат и ошибки

В stdin прямого CLI передаётся одна строка UTF-8 без BOM, максимум 4096 байт до необязательного перевода строки. Закройте stdin после записи. Поддерживается версия `v:1`, дополнительные или повторяющиеся параметры отклоняются. Поиск учитывает регистр. Ответ поиска содержит `{"ok":true,"entry":{"id":"…","title":"…","type":"…"}}`. Чтение возвращает `{"ok":true,"encoding":"base64","value":"…"}`. Максимальный размер исходного поля — 1 МиБ. Код выхода `0` означает успех. При ошибке код выхода `1`, ответ имеет вид `{"ok":false,"error":"…"}`.

| Код | Действие |
| --- | --- |
| `unavailable` | Проверьте флаг запуска, локальный сеанс и завершение предыдущего запроса. Такой ответ также возможен после отмены соединения или тайм-аута. |
| `locked`, `busy` | Разблокируйте приложение или дождитесь завершения открытого диалога либо операции. |
| `denied` | Владелец отклонил подтверждение или повторная проверка не прошла. |
| `stale` | Состояние записи изменилось во время подтверждения или исполнения. Снова запросите запись. |
| `not_found`, `ambiguous` | Проверьте ID или точное название. |
| `too_many` | Уточните поиск SSH по имени пользователя, порту или псевдониму. Верхняя граница ответа — 16 кандидатов. |
| `unavailable_field` | Проверьте тип записи, имя поля и видимость строки. |
| `invalid_request`, `too_large` | Исправьте формат или размер данных. |
| `ssh_disabled` | Включите команды SSH в разделе «Настройки → Безопасность». |
| `agent_access_disabled` | Для общего поиска или чтения полей требуется запуск с `--agent-access`. |
| `ssh_binding_not_found`, `ssh_binding_ambiguous`, `ssh_identity_missing` | Проверьте ID записи, наличие приватного ключа и точность привязки машины, пользователя и порта. |
| `ssh_host_key_failed` | Сверьте отпечаток сервера и исправьте запись в пользовательском `known_hosts`. |
| `ssh_auth_failed`, `ssh_askpass_failed`, `ssh_passphrase_unsupported` | Проверьте ключ, сохранённую парольную фразу и возможность аутентификации на сервере. |
| `ssh_launch_failed`, `ssh_connection_failed` | Проверьте наличие системного OpenSSH Client и доступность выбранного SSH-сервера. |
| `ssh_key_staging_failed`, `ssh_cleanup_failed` | Проверьте локальный каталог Temp и доступ к нему. После ошибки очистки перезапуск TokenBucket запускает проверку оставшихся временных каталогов. |
| `ssh_timeout`, `ssh_output_limit` | Уточните длительность и объём вывода команды перед новым запросом. |

## Границы доступа

Интерфейс использует локальный именованный канал Windows с доступом для текущей учётной записи и проверкой сеанса. Windows отклоняет удалённые подключения. Запросы обрабатываются по одному, подтверждение одного поля ожидается до 60 секунд. По умолчанию выбран отказ. Проверяйте название, поле и номер строки в диалоге. PID относится к процессу, подключившемуся к каналу. Личность программы или агента, запустившего помощника, по этому PID не подтверждается. Механизм предполагает доверие к Windows и к процессам владельца, у которых уже есть доступ к его сеансу. [Права доступа к именованным каналам](https://learn.microsoft.com/en-us/windows/win32/ipc/named-pipe-security-and-access-rights), [режим локальных подключений](https://learn.microsoft.com/en-us/windows/win32/api/namedpipeapi/nf-namedpipeapi-createnamedpipew).

Успешный `read` передаёт значение вызывающему процессу. Блокировка отменяет ещё не отправленную выдачу. Полученные агентом данные отозвать невозможно. Base64 сохраняет байты и не шифрует их. История агента, инструмента или модели может сохранить ответ. Если агенту нужно выполнить команду с токеном, используйте временную выдачу переменной окружения прямо в доверенный процесс через приложение. Для удалённой команды используйте `tokenbucket_ssh_exec`. Приватный ключ и парольная фраза остаются в локальном контуре TokenBucket и OpenSSH. Данные, выведенные удалённой командой, доступны вызывающей программе. Мастер-пароль и подтверждение Hello вводятся только в диалоге приложения.

Обрыв соединения и истечение срока согласия завершают запрос без ответа. Системный диалог Windows Hello при этом может оставаться открытым. Следующий запрос доступен после завершения системной проверки.
