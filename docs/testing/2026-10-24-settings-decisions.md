Successfully created candidate files are removed on pre-commit error; verified safety copies remain. Cost: a rare failed low-level write can leave an encrypted fragment; no unproven path is destroyed.

Cost: caller must treat committed plus error as an actual replacement requiring locked recovery, never as no-op.

Prepared snapshots bind both counters; explicit cancel and lock invalidate them. Cost: one private counter and request field, exercised by password and delayed-Hello cancellation tests.
Ruling: keep the shared RestoreResult outside the future so a late wait error cannot erase the factual committed state. No Outcome.file is used for backup preparation; it cannot replace the live encrypted image. Cost: one small result allocation per restore, no extra key/model lifetime in prepared state.

Cost: encrypted bytes retained during the prompt, no key/model and no authority to restore.
