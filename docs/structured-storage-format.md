# Структурированное хранение: CBOR v4

Контейнер TBVK, KDF, AEAD и способы разблокировки не изменены. Читаются модели v1–v4; запись и защищённый экспорт создают v4. Номера прежних типов сохранены.

| Тип | Номер | Полезные поля |
| --- | --- | --- |
| API-токен | 0 | прежний token |
| Логин и пароль | 1 | прежние login/password |
| SSH-ключ | 2 | прежние точные байты ключей и фраза |
| Простое значение | 3 | parameterName, plainValue, valueFormat |
| Текстовый файл | 4 | fileName, bytes, sourceSnapshot, visibleLines |

К прежним 19 CBOR-полям записи добавлены `key`, `value`, `format`, `fileName`, `fileBytes`, `fileSnapshot`, `fileVisible`, `sourceId`, `sourceLine`. `value` и `fileBytes` — byte strings; `format` — `text`/`ip`/`url`; номера видимых строк — строго возрастающие uint с нуля; `sourceLine` — signed integer, `-1` при отсутствии источника. Неактивные новые поля пусты. Старые неактивные полезные поля типов 0–2 не очищаются при чтении.

Ограничения: 10 000 записей, 8 уровней групп, 64 МиБ сериализованной открытой модели, 1 МиБ UTF-8 на значение или файл. Простое значение — одна строка без NUL/CR/LF и Unicode-разделителей строк. Имя параметра необязательно, до 128 печатных символов; правила переменных окружения проверяются отдельно, без автоматического усечения имени.

Текстовый файл содержит один канонический массив UTF-8 без NUL, до 50 000 строк. BOM, CRLF/LF/CR, комментарии, пустые строки и завершающий перевод сохраняются. Пустое тело и только BOM дают ноль строк; завершающий перевод добавляет пустую строку. Неизменённое тело не нормализуется при сохранении метаданных. Реальная правка задаёт LF, сохраняет исходный BOM и сбрасывает видимость с подтверждением. Снимок неизменяем; редактирование копии создаёт новый UUID.

Секретные и неизвестные строки скрыты по умолчанию. В глобальный поиск входят только разрешённые строки и простые значения без reverify. Повторная проверка имеет приоритет над показом и поиском. Отдельный показ ограничен общим сроком 5/10/15/30 секунд; блокировка убирает содержимое представлений. Копирование идёт через общий ClipboardGuard, целый файл требует отдельного подтверждения. Для точных байтов используйте сохранение файла: приложения могут нормализовать текст буфера.

TXT-разбор не выполняет команды, подстановки и escape-последовательности. Служебные пробелы вокруг имени убираются; некавыченные значения после `=` сохраняют свои пробелы, парные внешние кавычки снимаются. Исходный снимок остаётся точным. Повторы — отдельные предложения. Точное совпадение пропускается по умолчанию, другое значение получает новую версию; замена выбирается явно и сохраняет UUID и метаданные. Неизвестное имя не попадает в публичные метаданные по догадке. Весь кандидат проверяется до записи, ошибки сохранения откатывают рабочую модель.

Рабочая запись может ссылаться на UUID снимка и исходную строку. Изменение рабочего значения не меняет снимок. Удалённый источник допустим и показывается как недоступный; существующий обязан быть текстовым снимком с допустимым номером строки. Сравнение проверяет доступ к обеим сторонам и показывает только «Совпадает» / «Отличается».

Первое сохранение v1–v3 требует отдельного согласия для текущего поколения сеанса и уникальной проверенной копии `vault.tb.before-upgrade-*`. Правило действует для обычной записи, импорта и смены пароля/режима. Отмена до фиксации не заменяет основной файл; если отмена пришлась на уже совершённую замену, результат сообщает о фактической записи, сеанс остаётся заблокированным. Перед отдельной миграцией реестра создаётся собственная `vault.tb.before-registry-migration-*`, даже на v4; успешная миграция заканчивается повторным открытием хранилища. Копии зашифрованы прежним способом и могут требовать прежний пароль.

Существующие неоднозначные записи и старые TXT, чьи оригинальные байты нельзя подтвердить, автоматически не преобразуются. Новые права MCP/API, синхронизация с источниками и автоматическая миграция данных владельца не добавлены.
