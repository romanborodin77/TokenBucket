## Предыдущее предложение архитектуры (до выбора Linux / Windows)

Пользователь попросил продолжать после создания RESUME.MD. Подготовлено предложение, ещё не утверждено:

- C++20, CMake, нативный Win32-интерфейс со стандартными доступными контролами и компоновкой выбранного макета; Windows 11 x64 как основная целевая платформа.
- Альтернативы UI: Qt Widgets (больше зависимостей), WinUI 3 (дополнительный runtime и инфраструктура). Рекомендация: Win32 для минимальной поставки; макет задаёт компоновку, не обещает точного воспроизведения браузерных стилей.
- Один версионированный зашифрованный файл, включая названия и метаданные; атомарная замена и последняя исправная зашифрованная копия.
- Режим мастер-пароля: ключ из пароля, аутентифицированное шифрование. Конкретные параметры KDF и формат ещё предстоит зафиксировать.
- Режим Hello: локальная защита ключа через DPAPI текущего пользователя плюс проверка Hello в интерфейсе. Это НЕ криптографическая привязка расшифровки к Hello; процесс той же учётной записи потенциально может вызвать DPAPI. Этот компромисс необходимо явно согласовать, не выдавать за TPM-защиту.
- Экспорт: независимое шифрование с отдельным паролем, перенос без зависимости от исходной учётной записи Windows.
- Буфер: исключение из системной истории и синхронизации, условная очистка только своего содержимого; запрет истории не блокирует чтение другими процессами.
- Быстрая вставка: подтверждение получателя и повторная проверка окна перед отправкой, без автоматического Enter; не обещать атомарную адресную доставку или поддержку повышенных окон через SendInput.

## Актуальное продолжение: Linux / Windows

- Пользователь ответил «ок» на предложение архитектуры, затем запросил кроссплатформенность и уточнил цели: Linux / Windows.
- Актуальная рекомендация: C++20 + Qt 6 Widgets + CMake вместо Win32 UI. Выбранная компоновка «Список и карточка» сохраняется. Версия Qt и зависимости ещё не зафиксированы.
- Общие части: интерфейс, модель записей, криптографический формат, мастер-пароль, импорт/экспорт. DPAPI не использовать как общий формат хранилища; он относится только к локальному Windows-способу защиты ключа.
- Windows Hello — только Windows. На Linux базовый способ разблокировки — мастер-пароль; биометрия Linux не согласована.
- Горячие клавиши, буфер обмена, события блокировки и вставка требуют платформенных реализаций и проверок.
- На Wayland нельзя обещать универсальную автоматическую вставку и идентификацию чужого окна. Возможности порталов и доступность backend зависят от окружения. Предлагаемый запасной сценарий — копирование с ручной вставкой; это ограничение ещё необходимо согласовать, если оно касается целевого окружения пользователя.
- На Linux не обещать универсальное исключение секрета из истории сторонних менеджеров буфера; проверять конкретное окружение.
- Следующий вопрос: какой дистрибутив Linux и рабочий стол использует пользователь (GNOME/KDE, Wayland/X11). Предложенный вариант по умолчанию при отсутствии предпочтений: Ubuntu 24.04 LTS x64 / GNOME Wayland, Windows 11 x64.
